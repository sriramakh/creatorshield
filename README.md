# CreatorShield AI — v0.1 (MVP)

Pre-publication policy-risk review for **YouTube Shorts** and **Instagram Reels**.
Upload a video (≤ 60 s) with its caption and hashtags; CreatorShield transcribes
speech, samples key frames, reads on-screen text, runs rule-based checks and an
AI review against a **versioned knowledge base of verified official policy pages**,
and returns a timestamped report with evidence, citations and suggested fixes.

> CreatorShield gives automated, heuristic guidance. It is not legal advice and
> **cannot guarantee** that a platform will not remove, restrict, demonetize or
> strike content, or suspend an account. The risk indicator is not a probability.

## Quick start (macOS, native — recommended on a 16 GB Mac)

Prerequisites (already present on the dev Mac mini): Homebrew `postgresql@17`,
`redis`, `ffmpeg`, `tesseract` + `tesseract-lang`, `chromaprint` (audio fingerprints),
Node ≥ 20, `uv`.

```bash
# one-time
createuser -s creatorshield 2>/dev/null; psql -d postgres -c "ALTER ROLE creatorshield PASSWORD 'creatorshield_dev'"
createdb -O creatorshield creatorshield; createdb -O creatorshield creatorshield_test
(cd backend && uv sync)                 # Python 3.13 venv
(cd frontend && npm install)
cp .env.example backend/.env            # then add your API key (see below)

# every time
scripts/dev.sh                          # Postgres, Redis, migrations, API, worker, frontend
open http://localhost:3000
scripts/stop.sh                         # stop app processes (--all also stops Postgres/Redis)
```

Logs: `var/logs/{api,worker,frontend}.log`. API docs: http://localhost:8000/docs

### AI provider configuration

Edit `backend/.env` (git-ignored, mode 600) and restart (`scripts/stop.sh && scripts/dev.sh`):

| Setting | Values |
|---|---|
| `AI_PROVIDER` | `openai` (currently configured), `anthropic`, or `mock` |
| `OPENAI_API_KEY` / `OPENAI_MODEL` | key; model (default `gpt-5`) |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | key; model (default `claude-opus-5-5`), `ANTHROPIC_EFFORT` |

Without a key, analyses still complete with **rule-based checks only** and the UI
says so. `mock` returns a single placeholder AI finding, labelled **MOCK** everywhere
(dashboard, findings, report) — it never pretends to be a real analysis.

### Connected accounts (analyse posts by link)

**New analysis → From your account** analyses posts you have already published
(or uploaded privately) — **only from accounts you connect, only through official APIs**:

| | What is analysed | Notes |
|---|---|---|
| **Instagram** (professional accounts) | Full video, via the official `media_url` | Instagram withholds the file for Reels with licensed audio (incl. its audio library) or copyright flags → caption + thumbnail review, clearly labelled. Attach your own file on that report (or while importing) for a full review cross-checked against the post. Reels > 60 s: first 60 s analysed |
| **YouTube** | Title, description, tags, hashtags; captions if `YOUTUBE_CAPTIONS_SCOPE=true` | YouTube's API policies forbid downloading video/audio → **metadata-only** unless you attach the original file. The file is then reviewed in full and cross-checked against the title, description, duration and captions. The YouTube copy is not downloaded |

No scraping, no `yt-dlp`, no anonymous links: ownership is verified server-side and
disconnecting revokes access (YouTube) and deletes everything imported through that account.

Setup (your developer accounts; credentials go in `backend/.env`):
1. **Instagram** — developers.facebook.com → create app → add *Instagram* (API setup with
   Instagram login) → add redirect URI `http://localhost:8000/api/connections/instagram/callback`
   → add your account as tester → set `INSTAGRAM_APP_ID` / `INSTAGRAM_APP_SECRET`.
   If Meta rejects an `http://localhost` redirect, use an HTTPS tunnel and set
   `API_PUBLIC_URL` / `INSTAGRAM_REDIRECT_URI` accordingly. Production use requires Meta App Review.
2. **YouTube** — Google Cloud → enable *YouTube Data API v3* → OAuth consent screen (Testing,
   add yourself as test user) → OAuth client "Web application" with redirect URI
   `http://localhost:8000/api/connections/youtube/callback` → set `GOOGLE_CLIENT_ID` /
   `GOOGLE_CLIENT_SECRET`. Production use requires Google verification of the YouTube scopes.
3. Restart (`scripts/stop.sh && scripts/dev.sh`) and connect on **Connected accounts**.

`TOKEN_ENCRYPTION_KEY` (generated by `scripts/dev.sh`) encrypts OAuth tokens at rest —
keep it; changing it invalidates stored connections.

### Provenance & rights (copyright review)

CreatorShield cannot query Content ID or Meta Rights Manager — nobody outside the
platforms can. Instead it looks for **where content may have come from** and checks it
against **what you have recorded a right to**:

| Check | Cost | What it catches |
|---|---|---|
| On-screen cues | free | Other accounts' `@handles`, broadcaster / studio / label names (Star Sports, Netflix, T-Series…), copyright notices; the AI review also looks for logos, scoreboards, letterboxed film, face-cams |
| **Catalogue** | free | Reposts of a client's earlier posts, and the **same footage under two different clients** (mirrored copies too). Index past posts on the **Catalogue** page — only a fingerprint is kept |
| **Rights ledger** | free | Your own channels, creator permissions, music / footage licences and paid brand agreements. Covered items stop being findings; a recorded brand mentioned without `#ad` becomes a **high** finding |
| YouTube look-alikes | free (100 of the daily quota units per search) | Re-uploads with similar titles and thumbnails. On request; needs `YOUTUBE_SEARCH_API_KEY` or a connected channel |
| Song identification | paid, **off** by default | Names commercial tracks in detected music (≈ $0.005 per 12 s clip, ≤ 2 clips). `MUSIC_ID_PROVIDER=audd` + `AUDD_API_TOKEN` |
| Web image search | paid, **off** by default | Stock, film/TV stills, news images and thumbnails matching key frames (≈ $0.0035 per frame, ≤ 4). `WEB_DETECTION_PROVIDER=google` + `GOOGLE_VISION_API_KEY` |

Paid lookups run only when a signal calls for them (music detected / third-party cues)
or when you click, reuse cached answers, and stop at `PAID_LOOKUPS_MONTHLY_BUDGET_USD`
(default $5). `mock` providers exist for demos and are labelled MOCK everywhere.

Each completed review offers an **evidence pack** (zip): report, manifest with the
file's SHA-256 and every match, the ledger records it relies on with their proof files,
and a dispute-note draft. Everything here is a lead or your own record — **not** a
copyright clearance, and not legal advice.

## Data handling

- Uploads are validated by extension *and* `ffprobe` (container, video stream, duration ≤ 60 s, size ≤ 200 MB).
- No accounts, IP addresses or original filenames are stored.
- Everything for an analysis (video, frames, transcript, report) is deleted after
  `RETENTION_HOURS` (default 72), on demand from the UI/API (`DELETE /api/analyses/{id}`),
  or immediately after processing with `DELETE_MEDIA_AFTER_ANALYSIS=true`.
- `python -m app.cli purge-expired | delete-all | check-kb` for maintenance.
- No social platform is scraped. Platform APIs are called only for accounts you connect, via official OAuth.
- Catalogue fingerprints (frame hashes + audio fingerprint, no media) are kept for
  `CATALOGUE_RETENTION_DAYS` (default 365; YouTube imports ≤ 30 days) so later videos can be
  matched; deleting an analysis or disconnecting an account deletes its fingerprint.
- Rights-ledger proof files stay until you delete the record.
- OAuth tokens are encrypted at rest and never returned by the API; imported YouTube data is kept ≤ 30 days.

### Sponsored-content review

Uploads and account imports accept declared commercial relationships and sponsor names.
These declarations are stored with the analysis and passed to the AI as untrusted user
assertions. Existing analyses without declarations remain supported.

Disclosure checks reject negated or uncertain wording, flag late/buried caption labels,
and check named sponsors separately. Accepted wording includes Ad, Advertisement,
Sponsored, Collaboration, Partnership, Employee, Free gift, Affiliate and Hindi labels.
The opening-caption check uses an 80-character review heuristic; it is not a legal
threshold or a measurement of the platform's actual caption truncation.

Detected wording does not establish adequate disclosure. On-screen label duration,
readability and prominence require human review; platform paid-promotion settings remain
unverified. The ASCI summary now includes the March 2025 technical-advice clarification.
India guidance is advisory; the tool does not determine applicable jurisdiction.

Run `alembic upgrade head` before starting the updated application. Rerun existing
analyses to apply the new disclosure checks; historical reports are not automatically rewritten.
